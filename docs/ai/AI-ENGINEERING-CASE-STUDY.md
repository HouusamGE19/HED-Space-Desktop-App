# AI Engineering Case Study — HED Space

## Context

My primary background is Java full-stack development. HED Space was deliberately different: a Windows desktop media application using Tauri, Rust, SQLite, JavaScript, and mpv.

I used coding agents such as **Codex and Hermes** to work across this unfamiliar stack. The point of the project is not to claim that Rust/Tauri is my primary expertise. It demonstrates that I can use AI coding agents productively while still owning the engineering outcome.

## What I owned

- Product direction and feature requirements.
- UI/UX decisions and visual iteration from real screenshots.
- Acceptance criteria for behavior.
- Deciding what the agent was allowed to change.
- Reviewing generated patches and rejecting broad or incorrect changes.
- Running the application and validating runtime behavior.
- Debugging failures with the agent rather than accepting the first answer.
- Repository hygiene, source validation, and publish readiness.

## What the agents helped with

- Exploring an unfamiliar repository and explaining the stack.
- Tracing behavior across Rust, Tauri commands, JavaScript, SQLite, and mpv integration.
- Proposing and implementing focused changes.
- Diagnosing bugs and integration problems.
- Reviewing diffs and identifying regressions.
- Running or suggesting validation steps.
- Iterating on UI behavior based on screenshots and runtime feedback.

## The operating model

I treat the coding agent as an engineering collaborator rather than an autocomplete tool.

A typical task follows this loop:

1. **Orient** — inspect repository state, relevant files, and constraints.
2. **Investigate** — trace the current behavior and establish evidence.
3. **Plan** — choose a small implementation path when the task is broad or risky.
4. **Implement** — keep the patch focused and preserve unrelated behavior.
5. **Verify** — run the narrowest checks that provide strong confidence.
6. **Review** — inspect the diff for regressions, security issues, and accidental scope expansion.
7. **Hand off** — state what changed, what was tested, and what remains uncertain.

## Example: media playback integration

HED Space launches local playback through mpv and uses a custom Lua OSC while the application keeps library and resume state in SQLite.

For work in this area, an agent can help inspect the Rust process-control layer, Tauri command wiring, JavaScript interactions, and player configuration. My responsibility is to define the intended playback experience, run the application on Windows, verify controls and resume behavior, and reject changes that break unrelated media flows.

This distinction matters: an agent can generate code, but a working desktop media experience still requires runtime validation and product judgment.

## Example: UI iteration from screenshots

The interface was iterated from real running application screenshots rather than treated as a one-shot generated design. The workflow is:

- provide the current screen and describe the visual or behavioral mismatch;
- ask the agent to identify the smallest relevant UI area;
- implement the focused change;
- run the application and capture the result;
- compare the result to the intended experience;
- continue with a targeted follow-up instead of restarting the task.

This is especially useful for cinematic layout, navigation, library cards, the player overlay, and atmosphere views where visual feedback is more useful than a text-only requirement.

## Verification used in this repository

The repository includes `scripts/validate-source.py`, which performs source-level checks across configuration, HTML, JavaScript syntax, SQLite schema expectations, Tauri command wiring, scanner behavior, and the custom mpv OSC integration.

Native Tauri/mpv behavior is still tested on Windows because source validation cannot replace runtime verification for process control, media playback, packaging, and OS integration.

## What this project demonstrates

HED Space is evidence of a broader skill: **AI-assisted software engineering across an unfamiliar stack**.

The skill is not “asking AI to write code.” It is being able to give an agent a clear outcome, constrain its scope, investigate with evidence, review what it changes, validate the result, and remain responsible for what ships.

> Note: this repository does not publish private agent transcripts. This case study documents the development method and the responsibilities I kept as the developer; it does not claim that every file or every line was generated by an agent.
